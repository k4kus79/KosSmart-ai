01. KosSmart AI (Autonomous Co-Living & Boarding House Assistant)

Sistem Multi-Agen Otonom untuk Pengelolaan Kos Modern

Membantu pemilik atau pengelola kos dalam mengelola pembayaran sewa, menangani keluhan fasilitas (maintenance), melayani pertanyaan calon penyewa (onboarding), hingga memantau aturan operasional secara otomatis.

Pelajari Blueprint Lengkap

02. Masalah Operasional Kos

Mengapa Pengelolaan Kos Tradisional Melelahkan?

Keterlambatan Pembayaran Sewa

Pemilik sering kerepotan mencatat tanggal jatuh tempo dari banyak kamar, sehingga sering harus menagih secara manual satu per satu.

Penanganan Perbaikan Lambat

Laporan kerusakan (AC bocor, lampu mati, keran rusak) sering terselip di chat WhatsApp pribadi, membuat perbaikan tertunda dan penyewa tidak nyaman.

Repetisi Pertanyaan Calon Penghuni

Harus menjawab pertanyaan dasar yang sama berulang kali ("Kamar kosong ada AC?", "Tarif listrik?", "Boleh bawa hewan?").

03 & 04. Workflow Tim & Supervisor-Worker Pattern

Cara Kerja Agen dalam Tim & Pola Kerja Sama

Sistem menggunakan alur kerja kolaboratif berbasis event & pipeline dengan pola **Supervisor-Worker**.

Worker

1. Tenant Inquiry Agent

Menjawab pertanyaan ketersediaan, fasilitas, dan aturan kos secara instan.

Tools: RAG berbasis dokumen peraturan kos & FAQ.
Worker

2. Billing & Collection Agent

Mengirim pengingat tagihan sewa, mencatat, dan mendeteksi keterlambatan.

Tools: Logika waktu + Gateway Pembayaran / Bank API.
Worker

3. Maintenance Agent

Menerima laporan kerusakan, membuat tiket, dan menugaskan staf perbaikan.

Tools: Computer Vision (baca foto) + Text Classification.
Supervisor

4. Property Manager Orchestrator

Mengkoordinasikan seluruh agen, status kamar, dan laporan pemilik.

Tools: Rule-based workflow & state machine.

4 Fase Workflow Otonom

  • Fase 1 (Inquiry & Onboarding): Agen Penyewa menjawab 24/7, jadwalkan survei, dan kirim draf sewa.
  • Fase 2 (Billing & Payment): Agen Keuangan pantau jatuh tempo, kirim WA, dan verifikasi transfer.
  • Fase 3 (Maintenance Ticketing): Agen Pemeliharaan analisis keparahan foto kerusakan & jadwalkan tukang.
  • Fase 4 (Operational Oversight): Agen Pengawas rekap tingkat hunian dan laporan bulanan pemilik.

Pola Kerja Sama (Supervisor-Worker)

Property Manager Orchestrator bertindak sebagai pengendali pusat.

  • • Jika Billing Agent mendeteksi telat bayar, ia lapor Orchestrator untuk membatasi akses smart lock atau kirim peringatan resmi.
  • • Jika Maintenance Agent terima laporan darurat (pipa jebol), ia koordinasi dengan Orchestrator untuk cari tukang terdekat.
05. Memory & State Architecture

Hal yang Perlu Disimpan di Memori Sistem

Sistem membagi manajemen penyimpanan data ke dalam 3 hierarki utama agar agen bekerja secara akurat.

Short-Term Memory (Session)

Konteks percakapan saat calon penyewa sedang menanyakan detail kamar atau tawar-menawar harga di sesi chat aktif saat ini.

Scope: Active Chat Session State

Long-Term Vector Memory

Dokumen panduan fasilitas, House Rules, dan riwayat tiket perbaikan untuk mendeteksi pola kerusakan (misal: AC kamar 204 sering rusak).

Scope: Knowledge Base & Vector DB

State / Relational Memory

Status hunian setiap kamar (Available/Occupied, Nama Penghuni, Kontak) & data keuangan operasional (Paid, Pending, Overdue).

Scope: Operational Database State Machine
